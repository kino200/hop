# HOP HWPX 메모리 암복호화 연동 계획

2026-11-15. DS-HWPX.

- 배경. 기존 WordCraft·GridCraft·DeckCraft와 동일한 정책·서명 신뢰 체계에 HOP를 추가한다.
- 문제. HOP의 일반 저장은 HWP 평문 임시 파일을 사용하고 HWPX 원본 저장을 제한한다. 보호 문서는 이 경로를 사용할 수 없다.
- 목표. 규약 5·net.golbin.hop 서명으로 HWPX를 메모리에서 열고 편집 후 암호문만 원자 저장한다. 새 문서는 HWP.EXE 자동암호화 정책을 검사한다.
- 비목표. HWP 바이너리·다른 형식 변환 지원, 운영 정책 완화, 완전한 한글 서식 충실도, 관리자·커널·물리 화면 촬영의 절대 차단.
- 제약. rhwp 고정 서브모듈은 읽기 전용으로 유지하고 HOP overlay와 native Rust 경계에서 구현한다. Windows/Linux 일반 기능과 기존 편집 규약 2·3·4를 유지한다. 보호 문서 통합 시험은 평문 파일을 새로 생성하지 않는다. 기존 일반 HOP 시험의 합성 임시 파일은 보호 문서 흐름과 구분한다.
- 구현. native 인증 채널·메모리 열기/암호문 저장, HWPX 메모리 내보내기 검증, WebView 비영속 데이터·디버그/출력/파일 우회 제한, DocumentSafer 편집기 선택과 실행을 연결한다.
- 검증. 원본/ACL/정책 보존·교차 앱 거부·실패 시 보존·파일 우회·UI 반출 회귀, pnpm과 Rust/Swift 집중 시험, 릴리스 서명 빌드 및 승인된 별도 시험 정책의 실제 앱 저장·재열람을 확인한다.
- 복구. 설치 전 기존 앱/연결 도구를 보존한다. 편집기와 연결 도구의 호환성을 함께 확인하고 실패 시 평문 저장으로 전환하지 않는다.
- 작업 브랜치. HOP codex/documentsafer-memory-hwpx, DocumentSafer refactor/abstract-external-app-handler. 요청 없이 커밋·push하지 않는다.

- 구현 경계 결정. 기존 긴 `lib.rs`, `state.rs`, `tauri-bridge.ts`는 일반 흐름을 유지하고 보호 전용 모듈 호출만 연결한다. 저장 IPC는 Tauri가 주입하는 창·상태 인수를 포함하므로 6개 인수를 사용한다. 소켓·권한 검증과 메모리/파일 경계는 각각 분리한다.

- 완료 검증. 새 HWPX 자동암호화와 기존 암호문 편집·재암호화 후 새 프로세스 재열람을 사용자와 확인했다. 암호문·문서 ID/ACL/정책·원본 해시·잠금 배지 검사와 최종 native 68개, Swift 23개(외부 입력 11개 skipped)가 통과했다. 상세 근거·정리 상태·미검증 범위는 docs/context-notes.md에 기록한다.
